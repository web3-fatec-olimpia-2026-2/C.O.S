# ADR 003 — Tipagem realista para campos de Endereço e Descrição

## Contexto
Durante a modelagem inicial da base de dados, o campo `numero_endereco` foi definido como `IntegerField` e o campo `descricao` como `CharField(max_length=100)`. Isso causaria falhas em produção, pois muitos endereços contêm letras (ex: "123-B", "S/N") e 100 caracteres são insuficientes para um prestador detalhar o serviço a ser realizado.

## Decisão
Alterámos o `numero_endereco` para `CharField(max_length=20)` e a `descricao` para `TextField()`, que permite texto longo sem limite restrito. Além disso, corrigimos o campo `prestador` para ser uma `ForeignKey`, estabelecendo o relacionamento correto entre as tabelas.

## Alternativa descartada
Manter o `IntegerField` e criar um campo extra de texto apenas para "letras do número". Descartado porque aumenta a complexidade desnecessariamente na hora de preencher os formulários e renderizar a interface gráfica.

## Consequência
O modelo reflete com muito mais precisão o mundo real, evitando que a aplicação quebre (Erro 500) quando um utilizador digitar um endereço não numérico. A mudança exigiu a geração de uma nova migração (`makemigrations`).
