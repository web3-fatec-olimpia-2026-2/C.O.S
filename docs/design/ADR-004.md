# ADR 004 — Adoção de Namespacing para Templates HTML

## Contexto
Ao tentar aceder à rota de listagem de ordens, o Django devolveu um erro `TemplateDoesNotExist`. O sistema procurou o ficheiro `lista.html` e não o encontrou no caminho esperado, pois não havia um padrão claro de onde guardar os ficheiros de interface de cada aplicação.

## Decisão
Adotámos o padrão de *template namespacing* nativo do Django. Todos os ficheiros HTML da app `ordens` deverão ser armazenados estritamente no caminho `ordens/templates/ordens/`.

## Alternativa descartada
Criar uma pasta global `templates/` na raiz do projeto (`core/`) e atirar todos os ficheiros HTML de todas as apps para lá. Descartado porque, à medida que o sistema crescer, poderá haver conflitos de nomes (ex: um `form.html` para utilizadores e outro `form.html` para ordens de serviço). 

## Consequência
A estrutura de pastas fica ligeiramente mais profunda e repetitiva, exigindo a criação manual de subpastas. O benefício é o isolamento total: a app `ordens` torna-se autossuficiente e livre de colisões com o resto do sistema.
