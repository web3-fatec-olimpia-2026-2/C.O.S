# ADR 008 — Gestão Centralizada do Fluxo de Navegação e Redirecionamento

## Contexto
Para garantir a segurança das rotas e a fluidez de navegação, o sistema precisa saber exatamente para onde enviar o usuário não autenticado que tenta acessar uma página protegida, ou para onde redirecioná-lo após um login ou logout bem-sucedido.

## Decisão
Configuramos as variáveis nativas do Django no arquivo `core/settings.py` (`LOGIN_URL = 'login'`, `LOGIN_REDIRECT_URL = 'pagina_inicial'`, `LOGOUT_REDIRECT_URL = 'login'`). Simultaneamente, adotamos o uso exclusivo de rotas nomeadas (`{% url 'login' %}`) em todos os links e botões (como o botão vermelho de logout) dos arquivos HTML.

## Alternativa descartada
Escrever URLs fixas diretamente no HTML (ex: `href="/usuarios/login/"`) ou gerenciar os redirecionamentos através de funções JavaScript após o clique no botão. Descartado porque a codificação rígida (hardcoding) de URLs dificulta a manutenção, e as rotas via JavaScript podem falhar se houver problemas de carregamento de scripts.

## Consequência
O fluxo de navegação torna-se robusto, seguro e altamente previsível. Se o endereço web da página de login mudar no futuro, não será necessário alterar nenhum arquivo HTML, pois o sistema de rotas nomeadas do Django se encarrega da atualização automática.
