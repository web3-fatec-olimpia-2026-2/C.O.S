# ADR 009 — Estruturação de Base e Namespacing de Templates do Front-end

## Contexto
O projeto está em sua fundação e os arquivos HTML irão se multiplicar rapidamente nas próximas sprints. Colocar todos os arquivos em uma única pasta tornaria o projeto desorganizado e propenso a conflitos de nomenclatura (ex: vários `home.html` de aplicativos diferentes).

## Decisão
Criamos a estrutura de pastas `usuarios/templates/usuarios/` (aplicando o template namespacing) e definimos dois templates inaugurais: `login.html` (para telas isoladas de acesso) e `home.html` (com cabeçalho e botão de logout), preparados para suportar a lógica de herança (`{% extends %}`) no futuro, além de carregar arquivos estáticos (`{% load static %}`).

## Alternativa descartada
Aglomerar todos os templates do Front-end na pasta principal `core/templates/` sem separação lógica por aplicativo, ou construir cada página do zero repetindo o código do cabeçalho HTML. Descartado porque impede a escalabilidade do código e viola o princípio DRY (Don't Repeat Yourself).

## Consequência
A equipe de desenvolvimento tem agora uma base sólida e modular para criar as próximas páginas do projeto. O encapsulamento protege a aplicação, mas exige que a equipe respeite sempre a árvore de diretórios ao adicionar novas telas.
