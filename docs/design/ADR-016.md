# ADR-013 — Painel Administrativo de Ordens de Serviço

| Campo | Valor |
| --- | --- |
| **Status** | Proposto |
| **Data** | 2026-11-16 |
| **Autor** | Claudinei Feliz |

---

## Contexto

Atualmente o sistema possui uma única tela de listagem de Ordens de Serviço acessível por todos os perfis, com controle de visibilidade aplicado apenas no nível dos dados. Com o crescimento das funcionalidades, identificou-se a necessidade de uma interface separada e otimizada para o perfil **Administrador**, oferecendo visibilidade completa, ferramentas de busca avançada, filtros e navegação que não se aplicam à visão do Prestador de Serviço. Essa separação também segue os princípios de **Interação Humano-Computador**, entregando interfaces adequadas às tarefas de cada perfil.

---

## Decisão

Implementar uma tela dedicada de listagem de Ordens de Serviço para o perfil Administrador, com as seguintes características:

- **Rota exclusiva:** `/ordens/admin/` — acessível apenas por usuários com perfil `ADMINISTRADOR`; usuários não autorizados recebem erro 403 ou são redirecionados para o login
- **Interface com barra lateral** de navegação, alinhada com o protótipo de alta fidelidade aprovado
- **Busca textual:** pesquisa por número da O.S., descrição e local
- **Filtros combinados:** por status e por prestador de serviço
- **Paginação:** 10 registros por página, ordenados da O.S. mais recente para a mais antiga
- **Identidade visual:** utilização exclusiva da paleta de cores oficial do projeto (`azul-marinho`, `verde-lima`, cores de status/prioridade), sem introdução de novos estilos fora do escopo definido
- **Separação de responsabilidades:** mantida a tela original `/ordens/` para os demais perfis, sem alteração de comportamento

---

## Implementação

| Arquivo | Alteração |
| --- | --- |
| `ordens/views.py` | Criada a view `listar_ordens_admin` com filtros, busca e paginação; controle de acesso por perfil |
| `core/urls.py` | Adicionada rota `/ordens/admin/` mapeando para a nova view |
| `ordens/templates/ordens/admin_lista.html` | Novo template com layout de barra lateral, formulário de busca e filtros, tabela com badges coloridos e controles de paginação |
| `core/static/css/styles.css` | Acrescentados estilos específicos da nova interface (prefixo `.adm-*`), sem sobrescrever estilos existentes |
| `ordens/tests.py` | Adicionados 4 testes automatizados: permissão de acesso, bloqueio para prestador, redirecionamento para anônimo e validação de parâmetros de filtro |

---

## Alternativas Consideradas

| Alternativa | Vantagens | Desvantagens | Decisão |
| --- | --- | --- | --- |
| **Reutilizar a tela existente com condicionais** | Menos arquivos no projeto | Código misto, difícil de manter, layout compromissado para ambos os perfis | ❌ Rejeitada |
| **Criar template estendido do base.html existente** | Reutilização de componentes | Barra lateral não se aplica às telas do prestador, excesso de condicionais no template | ❌ Rejeitada |
| **Nova view + template dedicado** | Código limpo, interface otimizada, testabilidade isolada | Mais um arquivo mantido | ✅ Aceita |

---

## Consequências

### Positivas

- Interface administrativa independente e livre para evoluir sem impacto nos prestadores
- Experiência de uso mais adequada: administrador tem ferramentas de gestão, prestador tem foco em execução e comprovação fotográfica
- Código isolado facilita testes, manutenção e revisão por parte da equipe
- Testes automatizados garantem que a restrição de permissão não seja quebrada em alterações futuras

### Negativas

- Duplicação mínima de estrutura de layout entre telas — será resolvido quando implementarmos o template base compartilhado
- Duas rotas de listagem que precisam ser lembradas pela equipe
