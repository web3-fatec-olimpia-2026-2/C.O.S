# ADR-020: Empacotamento com Docker e Hospedagem no Render

## Contexto

O sistema C.O.S. (Controle de Ordens de Serviço) foi desenvolvido em Django 5.2 e utiliza a biblioteca `WeasyPrint` para geração de relatórios de O.S. em PDF, além do driver `psycopg2` para conexão com PostgreSQL. 

Ambientes PaaS baseados apenas em runtimes Python nativos geralmente não incluem pré-instaladas as bibliotecas gráficas de sistema operacional exigidas pelo WeasyPrint (`libpango-1.0-0`, `libpangoft2-1.0-0`, `libharfbuzz0b`, `shared-mime-info`), o que provoca falhas na exportação de PDF em produção. Além disso, a equipe precisa de uma solução de hospedagem gratuita, reproduzível e com deploy contínuo integrado ao GitHub.

## Decisão

Adotar o empacotamento da aplicação via **Docker** (`Dockerfile` baseado em `python:3.11-slim`) utilizando **Gunicorn** como servidor WSGI e hospedagem no **Render** (plano *Free*), com execução automática de `collectstatic` no build e `python manage.py migrate` na inicialização do contêiner.

## Alternativas Consideradas

* **Runtime Python nativo no Render (com `build.sh`):** Descartado devido à ausência das dependências nativas de sistema operacional para renderização de PDFs via WeasyPrint.
* **Hospedagem em VPS tradicional (Ubuntu/Nginx manual):** Descartada pelo maior custo operacional de manutenção, configuração manual de certificados SSL e ausência de plano gratuito equivalente ao do Render.

## Consequências

* **Positivas:**
  * Paridade total entre o ambiente de build e produção, eliminando falhas por falta de bibliotecas do sistema operacional.
  * Deploy automatizado a cada push/merge na branch `main`, com aplicação automática das migrações do banco antes de subir o servidor.
  * HTTPS gerenciado automaticamente pelo Render.
* **Negativas:**
  * Tempo de build ligeiramente maior devido à instalação de pacotes APT na criação da imagem Docker.
  * No plano gratuito do Render, a instância entra em hibernação (*spin down*) após 15 minutos de inatividade, ocasionando latência de ~30–50 segundos na primeira requisição após o repouso.
